# Монетизация и удержание в idle/кликер-играх на Яндекс Играх

Переносимая инструкция: механики, правила площадки и грабли, собранные на
практике. Ничего специфичного для конкретной игры — только то, что применимо
к любому кликеру или idle с валютой, прокачкой и наградами.

**Как пользоваться в новой сессии:** загрузите этот файл и скажите, какие
разделы применить. Числа в разделах «рекомендую» — отправная точка, их можно
двигать. Числа в разделах «лимит платформы» двигать нельзя.

Парная инструкция — `idle-economy-balance.md` (кривые цен, ступени контента,
сброс прогресса, узкие места, измерение баланса). Здесь про то, **когда и за
что** давать награду, там — **сколько**.

---

# 1. Общий принцип

Порядок приоритетов для idle-игры:

1. **Rewarded (за награду)** — основа дохода. Игрок сам решает смотреть, поэтому
   раздражения нет, а ставка за показ выше межстраничной.
2. **Удержание** — без возвращающихся игроков любая реклама бессмысленна.
3. **Межстраничная (принудительная)** — добавлять последней и осторожно. Легко
   испортить удержание и заработать жалобы.

Практическое правило: чем больше **добровольных** слотов, тем меньше нужна
принудительная реклама. Игрок, посмотревший 5 роликов по своей воле, приносит
больше и уходит реже, чем игрок, которому 5 раз показали межстраничную.

---

# 2. Rewarded-реклама

## 2.1. Где брать слоты

Универсальные, подходят почти любой idle-игре:

| Слот | Награда | Когда предлагать |
| --- | --- | --- |
| **Ускорение** | мгновенно завершить текущее ожидание | есть таймер/прогресс |
| **Множитель дохода** | x2 на N минут | всегда доступен кнопкой |
| **Удвоение офлайн-дохода** | ещё столько же, сколько накопилось | в окне возвращения |
| **Удвоение ежедневной награды** | x2 к бонусу за вход | в окне ежедневного бонуса |
| **Удвоение награды за задание** | x2 к выплате за квест/заказ | при получении награды |
| **Смена задания** | заменить неудобный квест | у каждого задания |
| **Продолжить после проигрыша** | вернуть попытку | если есть фейл-стейт |
| **Бесплатная валюта раз в N минут** | небольшая сумма по кулдауну | отдельная кнопка |

Чем больше слотов, тем выше суммарный доход — при условии, что **каждый слот
предлагает, а не требует**. Кнопка «посмотреть за награду» никогда не должна
быть единственным способом продолжить.

## 2.2. Правила, нарушение которых видно модерации

- Ролик стартует **только по явному нажатию** игрока. Никогда сам.
- **Звук игры глушится на время ролика.** Важно: страница при показе рекламы
  **не теряет фокус**, поэтому `visibilitychange` не сработает — глушить надо
  вручную в `onOpen` и возвращать в `onClose`.
- Награда выдаётся в `onRewarded`. При ошибке — на ваше усмотрение, но лояльнее
  выдать (игрок не виноват, что реклама не загрузилась).
- Кнопка не должна стоять вплотную к обычным кнопкам действия — случайные
  клики по рекламе платформа расценивает как фрод.

## 2.3. Готовый код

```js
function showRewarded(onReward) {
    if (!ysdk || !ysdk.adv) { onReward(); return; }   // вне платформы — сразу
    let paid = false;
    const pay = () => { if (!paid) { paid = true; onReward(); } };
    try {
        ysdk.adv.showRewardedVideo({ callbacks: {
            onOpen:     () => audioSuspend(),
            onRewarded: pay,
            onClose:    () => audioResume(),
            onError:    () => { audioResume(); pay(); },
        }});
    } catch (e) { onReward(); }
}
```

Флаг `paid` обязателен: `onError` может прийти **после** `onRewarded`, и без
защиты награда выдастся дважды. Это реальный дубликат, а не теоретический.

## 2.4. Кулдауны

Чем короче кулдаун, тем больше показов. Если слот не ломает баланс —
кулдаун 30–60 секунд. Длинные кулдауны (5+ минут) оправданы только там, где
награда действительно сильная.

Слоты без кулдауна вообще (смена задания, удвоение конкретной награды) — самые
доходные, потому что упираются только в желание игрока.

# 3. Межстраничная реклама

## 3.1. Главное про неё

**Частотой управляет сама платформа.** Если позвать слишком часто, показа не
будет, а `onClose` вернёт `wasShown: false`. Поэтому:

- собственную паузу отсчитывайте **от факта показа**, а не от попытки;
- при `wasShown: false` возвращайтесь раньше (показ был бесплатным по времени).

Площадка прямо не советует показывать межстраничную **во время активной игры** —
случайные клики классифицируются как фрод.

## 3.2. Где показывать

Безопасные моменты:

- **простой** — игрок N секунд ничего не нажимает (самый безопасный);
- **естественные паузы** — конец уровня/забега, престиж, закрытие окна
  возвращения из офлайна.

Условия, которые стоит проверять все сразу:

```js
function adAllowed() {
    if (!booted || adBusy) return false;
    if (document.hidden) return false;                    // показ в фон = мимо
    if (Date.now() < nextAdAt) return false;              // пауза не вышла
    if (document.querySelector('.sheet.open, .modal.open')) return false;
    if (boostActive()) return false;                      // не рвём оплаченный бонус
    return true;
}
```

## 3.3. Код

```js
const AD_IDLE_S = 30, AD_GAP_S = 210, AD_WARMUP_S = 90, AD_RETRY_S = 45;
let nextAdAt = 0, lastInputAt = 0, adBusy = false;

function showInterstitial() {
    if (adBusy || !ysdk?.adv?.showFullscreenAdv) return;
    adBusy = true;
    const finish = wasShown => {
        adBusy = false;
        audioResume();
        nextAdAt = Date.now() + (wasShown ? AD_GAP_S : AD_RETRY_S) * 1000;
    };
    try {
        ysdk.adv.showFullscreenAdv({ callbacks: {
            onOpen:  () => audioSuspend(),
            onClose: was => finish(!!was),
            onError: () => finish(false),
        }});
    } catch (e) { finish(false); }
}
```

Плюс `AD_WARMUP_S` — тишина в начале сессии, чтобы не встречать игрока рекламой.

## 3.4. Стоит ли добавлять

Честно: **межстраничная почти всегда ухудшает удержание**. Если игра ещё не
набрала аудиторию, разумнее выжимать rewarded и вернуться к принудительной
позже, когда будет с чем сравнивать по метрикам.

# 4. Ежедневные бонусы и серия заходов

## 4.1. Схема

- Цикл из **7 дней**, награда забирается раз в сутки.
- Заходил вчера — серия продолжается. Пропустил день — серия обнуляется.
- Награда растёт внутри цикла, на последнем дне — заметный скачок.
- Премиальная валюта — на 3-й и 7-й день, остальные дни обычная.

## 4.2. Что почти все делают неправильно

**Фиксированные суммы.** Награда «500 монет» на первой неделе щедрая, а через
месяц — мусор, и механика перестаёт работать именно на тех, кого удерживает.

Привязывайте награду к текущему темпу игрока:

```js
// доход игрока за минуту, умноженный на растущий коэффициент дня
const dayReward = i => Math.max(MIN_REWARD, Math.round(playerIncomePerSec * 60 * (2 + i)));
```

**Показ новичку.** Окно «С возвращением! Серия: 1 день» на первом же запуске
выглядит абсурдно, а ещё перекрывает обучение. Показывайте только тем, кто уже
прошёл туториал или имеет прогресс — серия начнётся со второго захода.

**Определение дня.** Сравнивайте строку даты (`YYYY-MM-DD`), а не таймстемпы:
иначе «сутки» будут ездить относительно того, во сколько игрок зашёл впервые.

```js
const today = new Date().toISOString().slice(0, 10);
const yesterday = new Date(Date.now() - 86400000).toISOString().slice(0, 10);
const pending = state.lastClaimDay !== today;
state.streak = (state.lastClaimDay === yesterday) ? state.streak + 1 : 1;
```

## 4.3. Rewarded поверх бонуса

Кнопка «Забрать x2» рядом с «Забрать» — один из самых конверсионных слотов:
игрок уже открыл окно и уже настроен получать.

# 5. Пассивный (офлайн) доход

Ключевая механика удержания в idle: даёт причину вернуться завтра.

## 5.1. Три независимых порога

Их часто путают в один, и это ошибка:

| Порог | Смысл | Рекомендую |
| --- | --- | --- |
| **MIN** | с какой отлучки вообще начисляем | 1 минута |
| **CAP** | потолок начисления | 8–12 часов |
| **REPORT** | с какой отлучки показываем окно-сводку | 4–5 часов |

**CAP должен быть больше REPORT.** Иначе появляется мёртвая зона: игрок,
вернувшийся между CAP и REPORT, получает уже максимум, но окна не видит и не
понимает, что ферма/шахта/завод работали.

Потолок 8–12 часов закрывает сценарий «зашёл утром — забрал за ночь». Это
главный сценарий возвращаемости в idle, ради него всё и делается.

## 5.2. Как считать

Два подхода:

- **Формула** — `доход_в_секунду × время`. Быстро, но врёт, если в игре есть
  ограничения (склад переполнился, ресурсы кончились, очередь встала).
- **Досчёт симуляцией** — прокрутить игровой цикл короткими шагами. Точно,
  учитывает все ограничения, но стоит времени.

Для честности лучше досчёт. Осторожно с шагом:

```js
const FF_STEP = 15;                                        // сек, шаг досчёта
const FF_MAX_STEPS = Math.ceil(OFFLINE_CAP / FF_STEP) + 10;

function fastForward(seconds) {
    let rem = seconds, guard = 0;
    while (rem > 0 && guard++ < FF_MAX_STEPS) {
        simulate(Math.min(FF_STEP, rem));
        rem -= FF_STEP;
    }
}
```

**Две грабли, на которых легко потерять деньги игрока:**

1. **Предел шагов задан числом.** Если написать `guard < 2000` при шаге 15 с,
   максимум досчитается 8 ч 20 мин — и потолок в 12 часов будет молча обрезан.
   Выводите предел из потолка, как в примере, тогда они не разъедутся.
2. **Соблазн увеличить шаг ради скорости.** За один шаг сущность обычно успевает
   не больше одного цикла «действие → результат». На длинном шаге доход
   просядет, и это не будет видно в тестах — только в жалобах.

Ориентир по стоимости: досчёт 12 часов на нагруженном состоянии — сотни
миллисекунд. Платится при загрузке, до показа интерфейса, поэтому терпимо.

## 5.3. Окно возвращения

Показывайте **что именно** накопилось, построчно, а не одним числом:

```
Тебя не было 7 ч. Производство работало:
  ⛏  Ресурс А        +34
  ⚙  Ресурс Б        +21
  🪙 Продано на      +48.2К
```

Так видна отдача от вложений в автоматизацию — это прямо мотивирует
докупать производителей. Одна строка «накоплено 68» такого эффекта не даёт.

Кнопка «Продолжить x2» за ролик в этом окне — обязательна.

## 5.4. Показ прогноза в интерфейсе

Строка «пока тебя нет, накопится ≈N» даёт повод вернуться. Но:

- показывайте её, **только когда доход реально пойдёт**. Если в игре есть
  условия (нужен определённый набор построек/работников/апгрейдов) — проверяйте
  их все, иначе цифра будет выдумкой;
- если условия не выполнены — **пустая строка**, а не уговоры «купите X».
  Реклама собственных механик в интерфейсе раздражает;
- помечайте приблизительность знаком «≈», если считаете формулой.

# 6. Инструменты удержания от площадки

## 6.1. Ярлык на главный экран

Самый прямой инструмент: игра появляется на экране устройства, и заход
перестаёт требовать поиска в каталоге. **За установку разрешено награждать.**

```js
// проверяем доступность
const r = await ysdk.shortcut.canShowPrompt();   // { canShow: boolean }
// показываем — обязательно из обработчика нажатия игрока
const res = await ysdk.shortcut.showPrompt();    // { outcome: 'accepted' | ... }
if (res.outcome === 'accepted') giveReward();
```

**Важно:** `showPrompt()` открывает нативный диалог, и без жеста пользователя
браузер может его не показать. Поэтому схема такая: своя карточка с
предложением → игрок нажимает «Добавить» → из обработчика зовём `showPrompt()`.

Предлагать один раз, отказ запоминать. Момент — когда игрок уже втянулся
(несколько минут игры или первое заметное достижение), а не на старте.

## 6.2. Запрос оценки

Отзывы влияют на позицию в каталоге, то есть на приток новых игроков.

```js
const can = await ysdk.feedback.canReview();     // { value, reason }
if (can.value) {
    const res = await ysdk.feedback.requestReview();   // { feedbackSent }
}
```

- `canReview()` **обязателен** перед `requestReview()`, иначе ошибка.
- Запросить можно **один раз за сессию**.
- Причины отказа: `NO_AUTH`, `GAME_RATED`, `REVIEW_ALREADY_REQUESTED`,
  `REVIEW_WAS_REQUESTED`, `UNKNOWN`.

Момент — сразу после яркого события: первый престиж, крупное достижение,
пройденная глава. Не на старте и не после проигрыша.

Предусмотрите запасной сценарий: если оценка недоступна, момент не должен
пропадать впустую — покажите что-то другое.

# 7. Обучение: как игрок вообще узнаёт про награды

Самый дешёвый способ поднять доход — не добавить ещё один слот, а объяснить уже
существующий. Кнопка «x2 за ролик» приносит ноль, пока игрок не понял, что она
делает. То же с офлайн-доходом: игрок, не знающий, что ферма работает без него,
не имеет причины вернуться завтра.

Это не «приятное дополнение» к разделам 2–5, а условие их работы.

## 7.1. Два разных механизма, не путать

| | Обучение | Контекстные подсказки |
|---|---|---|
| Порядок | линейный: шаг 1 → 2 → 3 | по условию, в любой момент |
| Кому | только новичку | **всем, включая давних игроков** |
| Про что | базовое действие игры | награды, автоматизация, офлайн |
| Прогресс | номер шага в сейве | множество показанных id |

Соблазн велик — дописать монетизацию четвёртым шагом обучения. Так делать
нельзя по двум причинам:

1. **Триггеры условные, а не последовательные.** «Наними работника» имеет смысл
   показывать, когда на работника хватает денег, а не когда игрок дошёл до
   шага 4. До этого подсказка — дразнилка.
2. **Ваша аудитория уже играет.** Если игра опубликована, у большинства игроков
   обучение давно пройдено, и в линейный сценарий они не вернутся никогда.
   Новую механику увидят только новички — то есть меньшинство.

Поэтому подсказки живут отдельной системой, а условие «обучение пройдено»
входит в их триггер как одно из требований.

## 7.2. Структура

```js
const TIPS = [
    {
        id: 'ad',                       // ключ в сейве, менять нельзя
        target: 'boostBtn',             // на что показываем
        text: () => t('Хочешь вдвое больше? Посмотри короткий ролик'),
        when: () => tutorialDone() && player.hasSoldSomething && !boostActive(),
    },
    {
        id: 'auto',
        target: 'shopButton',
        text: () => t('Наними помощника — доход пойдёт и без тебя'),
        when: () => tutorialDone() && !hasAnyWorker() && coins >= firstWorkerCost(),
    },
];

let tipNow = null;
function tipTick() {                     // раз в секунду
    if (tipNow || !state) return;
    if (document.querySelector('.sheet.open, .modal.open')) return;   // не поверх окон
    const tip = TIPS.find(x => !state.tips[x.id] && x.when());
    if (!tip) return;
    show(tip);
    setTimeout(closeTip, 11000);         // сама уходит
}
// любое действие игрока снимает подсказку: она уже сделала своё дело
document.addEventListener('pointerdown', () => tipNow && closeTip(), true);

function closeTip() { state.tips[tipNow.id] = true; save(); hide(); }
```

Правила, которые стоят за этим кодом:

- **одна за раз** — очередь из пузырей читается как баннер, а не как помощь;
- **один раз навсегда** — флаг в сейве, а не в сессии;
- **сама исчезает** (10–12 с). Висящая насовсем подсказка хуже, чем её
  отсутствие: игрок начинает её обходить взглядом;
- **любой тап снимает** — в том числе тап по той самой кнопке;
- **никогда поверх открытой панели или модального окна.** Порядок важности:
  окно возвращения → ежедневный бонус → подсказка. Подсказка ждёт;
- **во время обучения молчат.** Два учителя одновременно — ни одного.

## 7.3. Момент показа

Правило одно: **показывать, когда механикой уже можно воспользоваться, и не
раньше.**

- про удвоение дохода — после первой продажи (игрок понял, зачем ему валюта),
  но **не когда удвоение уже включено**: подсказка укажет на кнопку, которая
  сейчас ничего не сделает;
- про автоматизацию — когда первый помощник по карману;
- про офлайн-доход — в момент, когда он впервые начал капать;
- про ежедневный бонус — он показывает себя сам окном, отдельная подсказка не
  нужна.

Показ «на всякий случай, вдруг пригодится» не работает: механика без
применения не запоминается.

## 7.4. Куда указывать

Стрелка сама по себе двусмысленна. Если внизу экрана два ряда кнопок, стрелка
визуально попадает между ними, и игрок нажимает соседнюю.

**Подсвечивайте сам элемент** на время подсказки — рамка и лёгкая пульсация:

```css
.tipTarget {
    position: relative; z-index: 16;      /* поверх затемнения, если оно есть */
    outline: 3px solid gold; outline-offset: 2px;
    animation: tipPulse 1.2s ease-in-out infinite;
}
```

**Грабли вёрстки.** Пузырь обычно позиционируется `position:fixed` + `left/top`
цели + `transform: translate(-50%, -100%)`. Ширина такого элемента считается
браузером **из остатка места справа от `left`, до применения `transform`**.
У кнопки в правой части экрана остаток равен нулю, и текст схлопывается в
колонку по слову в строке. Лечится явной шириной:

```css
.bubble { position: fixed; width: 230px; transform: translate(-50%, -100%); }
.bubble.side { transform: translate(-100%, -50%); }   /* привязка справа */
```

## 7.5. Старые сейвы

Поле `tips` появляется в сейве позже самой игры, поэтому при загрузке его
нужно достроить:

```js
if (!save.tips || typeof save.tips !== 'object') save.tips = {};
```

Без этого первый же `state.tips[id]` уронит игру у всех, кто играл до
обновления, — то есть ровно у той аудитории, ради которой подсказки и делались.

Заодно решите обратный вопрос: **показывать ли новую подсказку тем, кто уже
играет?** Обычно да — они и есть основная аудитория. Но если механика в игре
давно и человек ею пользуется, подсказка выглядит глупо. Ставьте в `when()`
проверку «ещё ни разу не воспользовался», а не «не видел подсказку».

## 7.6. Чего не делать

- **Не объясняйте всё.** 2–3 подсказки на игру. Каждая следующая обесценивает
  предыдущие;
- **не превращайте подсказку в уговор.** «Посмотри ролик — получишь x2» это
  объяснение; «Смотри ролики чаще!» это баннер, и его будут закрывать не читая;
- **не блокируйте интерфейс** затемнением с единственной кликабельной кнопкой.
  Обучение, из которого нельзя выйти, — частая причина ухода на первой минуте;
- **не показывайте подсказку про платное действие раньше, чем игрок сможет его
  совершить.**

## 7.7. Что проверять

- во время обучения подсказок нет;
- подсказка появляется ровно при выполнении условия и **не раньше**;
- показывается один раз: после закрытия и перезагрузки не возвращается;
- снимается тапом; исчезает сама по таймеру;
- под открытой панелью или модальным окном ждёт, а после закрытия показывается;
- старый сейв без поля `tips` грузится и получает его;
- пузырь не выходит за края экрана и не схлопывается в колонку — проверить у
  **правого** края и на узком экране (320 px).

# 8. Технические требования, ломающие релиз

Это не про монетизацию, но без них игру не опубликуют.

## 8.1. GameReady

Сигнал готовности обязан уходить **до того**, как игра станет доступна для
действий игрока.

```js
function boot() {
    prepareEverything();
    ysdk.features.LoadingAPI?.ready();          // сначала сигнал…
    document.body.classList.add('ready');       // …и только потом показываем UI
}
```

Отправлять ровно один раз и **на всех путях запуска**, включая ветку, где SDK
ответил с задержкой или не ответил вовсе.

## 8.2. Автоопределение языка

```js
const lang = ysdk.environment.i18n.lang;   // 'ru', 'en', 'tr', …
```

Три требования, каждое роняет модерацию:

1. Язык определяется **до первой отрисовки** интерфейса. Переключение «на
   глазах у игрока» считается отсутствием автоопределения.
2. Свойство `ysdk.environment.i18n.lang` должно **фактически читаться на каждом
   запуске**. Дебаг-панель площадки определяет использование именно по факту
   обращения: если у вас сохранён ручной выбор игрока и код выходит раньше, чем
   дойдёт до SDK, панель покажет «I18N is not used». Читайте язык платформы
   первым делом, а оверрайды применяйте после.
3. Автоопределённый язык **не сохранять** в `localStorage`. Иначе он перекроет
   язык платформы на следующем заходе, и автоопределение сработает один раз за
   всю жизнь установки. Сохранять только явный выбор игрока.

## 8.3. Облачные сохранения

```js
player.setData({ save: raw }, flush);   // flush по умолчанию false
```

| Лимит платформы | Значение |
| --- | --- |
| Размер данных | 200 КБ на игрока |
| Частота запросов | 100 за 5 минут |

`flush: false` — запись копится и уходит пачкой, это бережёт лимит. Но
накопленное **может не успеть уйти**, если игрок закрывает вкладку. Поэтому
дожимайте при уходе со страницы:

```js
document.addEventListener('visibilitychange', () => {
    if (document.hidden) saveNow({ flush: true });
});
window.addEventListener('pagehide', () => saveNow({ flush: true }));
```

Сам дожим тоже ограничьте по частоте (раз в 3 секунды), иначе дёрганое
переключение вкладок сожжёт лимит.

## 8.4. Лидерборды

```js
ysdk.leaderboards.setScore(name, score);          // актуальный API
ysdk.leaderboards.getEntries(name, opts);
```

- `getLeaderboards()` **устарел**; у объекта из него методы называются иначе
  (`setLeaderboardScore` / `getLeaderboardEntries`). Если поддерживаете оба
  поколения — приводите к одному виду, иначе получите тихие падения.
- Писать результат и видеть своё место может **только авторизованный** игрок
  (`player.isAuthorized()`). Неавторизованному показывайте предложение войти
  через `ysdk.auth.openAuthDialog()`, а не пустую таблицу.
- `includeUser: true` для неавторизованного — ошибка запроса.
- Лимиты: запись — 1 раз в секунду, чтение — 20 запросов за 5 минут. Запись
  троттлите, выдачу кэшируйте (30 секунд достаточно).
- `quantityTop` 1..20, `quantityAround` 1..10.
- **Экранируйте имена игроков** перед вставкой в HTML — это чужой ввод.
- Не пишите нулевой результат: таблица забьётся пустыми записями.

## 8.5. Прочее из чеклиста

- Контекстное меню браузера отключить: `document.addEventListener('contextmenu',
  e => e.preventDefault())`. Вешать при загрузке скрипта, а не после инициализации.
- Звук паузится при потере фокуса вкладки.
- Никаких JS-ошибок в консоли.
- Проверить вёрстку на 320×568, 360×640, 640×360, 768×1024, 1280×720.

# 9. Баланс: чего не сломать наградами

**Подарки не должны идти в метрики прогресса.** Если в игре есть престиж,
рейтинг или расчёт «дохода в секунду», начисляйте награды за рекламу, ежедневные
бонусы и квесты **отдельно** от обычного заработка:

```js
function earn(amount)  { coins += amount; lifetimeEarned += amount; incomeAcc += amount; }
function grant(amount) { coins += amount; }   // подарки: только монеты
```

Иначе получится: подарки ускоряют престиж, престиж ускоряет доход, раздутый
доход раздувает следующие подарки. И заодно врёт прогноз офлайн-дохода, если он
считается по темпу заработка.

**Множители не должны складываться бесконечно.** Если у вас есть x2 за ролик,
x2 за офлайн и x2 за ежедневный бонус — проверьте, что они не перемножаются в
одном окне до x8.

# 10. Как это тестировать

Настоящий SDK доступен только на площадке, поэтому подменяйте его моком до
загрузки скриптов игры (в Playwright — `page.addInitScript`).

Мок должен считать вызовы и отдавать колбэки:

```js
window.YaGames = { init: () => Promise.resolve({
    environment: { i18n: { lang: 'ru' } },
    getPlayer: () => Promise.resolve({
        isAuthorized: () => true,
        getData: () => Promise.resolve({}),
        setData: (d, flush) => { calls.push({ flush }); return Promise.resolve(); },
    }),
    features: { LoadingAPI: { ready: () => calls.push('ready') } },
    adv: {
        showRewardedVideo: ({ callbacks }) => {
            calls.rewarded++;
            callbacks.onOpen?.();
            callbacks.onRewarded?.();
            callbacks.onClose?.(true);
        },
        showFullscreenAdv: ({ callbacks }) => callbacks.onClose?.(true),
    },
    // …leaderboards, shortcut, feedback
})};
```

Что проверять обязательно:

- каждый rewarded-слот: ролик показан, награда пришла ровно один раз, звук на
  время ролика заглушён;
- реклама не стартует сама;
- ежедневный бонус: серия растёт, пропуск обнуляет, в один день награда одна;
- офлайн: короткая отлучка не показывает окно, длинная показывает; доход за
  потолок **пропорционален времени** (это ловит обрезку из 5.2);
- подарки не увеличивают метрики прогресса;
- GameReady ушёл раньше, чем интерфейс стал доступен — замерять **внутри
  вызова** `ready()`, а не наблюдателем за DOM (наблюдатель подключается позже
  и даёт ложный успех);
- обучение и подсказки — по списку из 7.7.

## 10.1. Возвращение после долгого отсутствия

Самый нагруженный путь в игре и при этом самый редко проверяемый: локально
досчёт офлайна почти всегда запускают на пяти минутах, а у игрока это 12 часов.
Прогоните **предельный** случай на развитой ферме и измерьте:

| Что мерить | Признак беды |
| --- | --- |
| вызовы `setData` | их больше 2–3 на один запуск |
| записи в `localStorage` | столько же, сколько шагов симуляции |
| длина массивов частиц/всплывающих чисел | тысячи |
| время до `ready()` | секунды |

Причина у всех четырёх одна: досчёт зовёт обычный игровой шаг, а тот на каждое
действие сохраняется, играет звук и порождает эффекты. За кадр это одна
операция, за ночь — тысячи.

```js
let catchUp = false;                      // идёт досчёт офлайна
function fastForward(seconds) {
    catchUp = true;
    try { /* … шаги симуляции … */ } finally { catchUp = false; }
}
function save()      { if (catchUp) return; /* … */ }   // сохранить один раз после
function spawnFx(..) { if (catchUp) return; /* … */ }
```

Замеренный масштаб на реальной игре: 2885 обращений к облаку при лимите
платформы 100 за 5 минут, 182 тысячи частиц в очереди и 10,9 с до сигнала
готовности. После защиты — 1 обращение и 1,1 с. **Ни одно из этих чисел не
видно в отладке на коротких отлучках.**

Там же проверьте: **офлайн-работа не должна засчитываться в дневные квесты.**
Иначе за ночь автоматика выполняет их сама, игрок заходит на готовые галочки, и
ежедневный цикл (а с ним и повод открыть сундук) исчезает. Считайте прогресс от
базы, сдвинутой на офлайн-прирост, сохраняя набранное вживую.

## 10.2. Повреждённый и чужой сейв

Сейв приходит из облака, а значит — с другого устройства и, возможно, из другой
версии игры. Проверьте, что игра **запускается** на: мусоре вместо JSON, пустом
объекте, `null` в обязательных полях, индексах предметов за пределами текущих
таблиц.

Две ошибки, которые стоят игроку всего прогресса:

1. **Возврат частично слитого состояния из `catch`.** Если объект-результат
   мутируется по ходу разбора, то в обработчике ошибки он уже испорчен — и
   отдавать надо **чистое** состояние, а не его. Иначе один битый сейв
   заклинивает запуск навсегда: игрок видит чёрный экран при каждом заходе и
   починить это сам не может.
2. **Подрезка чужого индекса к границе таблицы.** `Math.min(i, LAST)` для
   предмета из будущей версии выдаёт самый дорогой предмет игры бесплатно.
   Неизвестный индекс — это «ничего», а не «максимум».

# 11. Порядок внедрения

Если делаете с нуля, в таком порядке:

1. Облачные сохранения и GameReady — без них не опубликуют.
2. Автоопределение языка.
3. Офлайн-доход с тремя порогами и окном возвращения.
4. 3–5 rewarded-слотов, включая удвоение офлайна.
5. Ежедневная серия с кнопкой x2.
6. **Подсказки про пункты 3–5** (раздел 7). Механика, о которой не знают,
   не приносит ничего — это самый дешёвый шаг в списке.
7. Ярлык на главный экран и запрос оценки.
8. Лидерборд, если механика позволяет.
9. Межстраничная реклама — в последнюю очередь и по метрикам.
